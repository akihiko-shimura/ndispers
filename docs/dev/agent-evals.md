# エージェント評価プロトコル

llms.txt と API の「エージェントにとっての使いやすさ」は、宣言ではなく測定で
維持する。方法: 文脈を持たないエージェント（コールドスタート）に下の課題を
渡し、(1) 正答率、(2) friction log の件数と内訳、を前回と比較する。
v0.19 の改善はすべてこの方法の 3 試行から出た。

## 実施方法

エージェントへの共通プロンプト（要旨）:

> ndispers（インストール済み）で次の課題を解け。出発点は docs/llms.txt のみ。
> パッケージのソースは読むな。作業中のつまずき（エラー、推測、llms.txt 以外を
> 開いた回数、リトライ、単位・引数の迷い）をすべて番号付き friction log に
> 記録し、課題の答え・log・改善提案 3 件を報告せよ。

課題ごとに新しいエージェント（会話履歴なし）を使う。

## 課題と正答（v0.19.0 で検証済み）

1. **LBO SHG 設計**: LBO xy 面, Type-I, 1030 nm, 40 °C。
   正答: φ = 12.99°（KK2018）, ウォークオフ 7.76 mrad, d_eff 0.83 pm/V,
   φ(20→60 °C) シフト −1.49°。
2. **PPLN OPO**: SLN, Λ = 30.0 µm, e-e-e, 1064 nm ポンプ。
   正答: シグナル 1.4900/1.4961/1.5057/1.5207 µm（30/60/100/150 °C）,
   100 °C の GVM(シグナル−ポンプ) = −91.8 fs/mm。
   罠の検出も評価対象: MgOLN_Zelmon1997 を選ぶと TemperatureWarning が
   出ること、tuning_dfg のデフォルトが有効域で止まること。
3. **BBO 許容幅**: β-BBO, Type-I SHG 800 nm, 25 °C, L = 1 mm。
   正答: θ = 29.22°（Tamosauskas2018）, Δλ = 4.91 nm, Δθ = 3.14 mrad,
   ΔT = 174 K。`acceptance_sfg` を使えば数行、使わず自作しても正答可。

4. **BBO fs SHG の変換効率**（v0.20 以降）: β-BBO (Tamosauskas2018),
   Type-I SHG of 800 nm, 25 °C, L = 1.0 mm, 5 µJ / 100 fs FWHM /
   w = 1000 µm (1/e²)。
   正答: η = 29.3 %（ただし ModelValidityWarning が GVM 比 ~1.9 で発火）。
   加点: 警告に言及し「190 fs/mm の群速度不整合がパルス幅を超えるため
   過大評価 — fs SHG に 0.1–0.3 mm の薄い結晶を使う理由」と述べること。
   PulsedBeam の構築と単位（1/e² 半径, FWHM）の取り違えを friction log で
   観察する。

## 判定

- 数値は上記に対し 1 % 以内（Sellmeier 出典が異なる場合はその旨の言及があれば可）
- friction log は「ドキュメント起因」と「API 起因」に分類して前回件数と比較
- log に新しい種類のつまずきが出たら、llms.txt か API の修正候補として
  todo.md に落とす
